# Phase 8 Elementor API and hook contract

**Release:** 0.8.0  
**Namespace:** `realestate-platform/v1` remains unchanged  
**Compatibility status:** official hook shape verified with a local contract fixture; actual vendor runtime **NOT VERIFIED**

## Official hooks

| Hook | Type | Contract used by REP |
|---|---|---|
| `elementor/loaded` | action | Deferred optional boot when Elementor is not loaded at core registration time |
| `elementor/dynamic_tags/register` | action | Receives the dynamic-tag manager; REP calls `register_group()` and `register()` |
| `elementor/query/{query_id}` | action | Receives `WP_Query`; REP mutates only the allowlisted public query arguments |
| `elementor_pro/forms/actions/register` | action | Receives the Pro action registrar; REP calls `register()` with one lead action |

The query integration uses `add_action()`, matching Elementor’s documented custom-query contract. It is not registered as a filter and has no return-value contract. The Pro action shape follows the official custom-action guide at <https://developers.elementor.com/docs/form-actions/add-new-action/>.

## Stable dynamic-tag catalog

Each catalog entry has `{id, title, entity, field, type}`. `type` is `text` or `url`; the runtime class supplies the group, category, name, title, and escaping behavior.

Representative stable IDs:

```text
rep_property_title
rep_property_price
rep_property_type
rep_property_status
rep_property_agent
rep_property_featured_image
rep_project_title
rep_project_type
rep_agent_public_phone
rep_agent_agency
rep_agency_license_number
rep_insight_topic
rep_insight_cta_url
```

The complete catalog is generated by `TagCatalog::definitions()` and is the single source for registration. Duplicate taxonomy prefixes are prohibited by construction.

## Context contract

```php
$value = $publicContext->resolve( string $entity, string $field );
```

The result is a scalar, a list of validated public attachment URLs, or `null`. It is never a private DTO or raw database row. The resolver requires a current published post whose type matches the requested entity. Relation values are returned only when the related Agent or Agency is itself published. Coordinate values pass through the configured privacy mode.

## Query contract

```text
rep_properties:  WP_Query -> SearchRequest -> public result IDs -> WP_Query post__in
rep_projects:    WP_Query -> public post_type/status bounds
rep_agents:      WP_Query -> public post_type/status bounds
rep_agencies:    WP_Query -> public post_type/status bounds
rep_insights:    WP_Query -> public post_type/status bounds
```

Recognized Property query variables are `rep_keyword`, `rep_reference`, the allowlisted canonical criteria keys, `rep_orderby`, `rep_page`, and `rep_per_page`. The adapter also accepts `s`, `paged`, and `posts_per_page` as bounded fallbacks. Unknown `rep_*` variables do not become SQL or arbitrary meta queries. The canonical service validates values, sorting, visibility, and pagination.

A failed canonical search produces a safe empty `post__in` set. A successful property query always sets `post_type=property`, `post_status=publish`, `ignore_sticky_posts=true`, and `no_found_rows=true`; this prevents private/draft expansion and prevents the same page being sliced twice.

## Elementor Pro form contract

Action name: `realestate_platform_lead`  
Label: `RealEstate Platform Lead`

Allowed field IDs and server targets:

| Field IDs | Target |
|---|---|
| `name`, `full_name` | `name` |
| `email` | `email` |
| `phone` | `phone` |
| `message` | `message` |
| `property_id` | `property_id` |
| `project_id` | `project_id` |
| `consent` | `consent` |
| `website_url` | `website_url` |
| `idempotency_key` | `idempotency_key` |

All other fields are ignored. The action adds `source=elementor`, invokes the shared public rate limiter, and delegates to `RequestService::submit()`. The field map is not an authorization mechanism: IDs are revalidated by the Phase 7 DTO/service path, and status, assignment, owner, workflow, notification, and audit fields are server-owned.

## Versioning

The IDs and hook names are public adapter contracts for 0.8.0. Additive catalog entries are allowed; changing the meaning of an existing ID requires a documented compatibility decision. The REST namespace and core service contracts are not changed by this adapter. No Elementor vendor class is referenced by core code before the corresponding optional registration path is entered.

## Failure and fallback behavior

- Elementor absent: core remains active; `availability()['elementor']` is false.
- Pro absent: no Pro form action is registered; dynamic tags/query adapters remain independent.
- ACF absent: no failure; the existing optional ACF adapter remains optional.
- Invalid public context: tag renders nothing.
- Invalid query: bounded empty result.
- Invalid form: generic failure with no workflow mutation.
- Delivery failure: inherited Phase 7 notification isolation; lead/request state remains authoritative.
